# 算法：定位与补测

## 输入与假设

输入是链路拓扑、每条探测实际经过的节点路径，以及 `pass / fail / missing` 结果。
推断器不推测路由；生成器用最短路径只是构造实验的一种方式。

候选集合为所有链路，再加一个健康状态。一个窗口内最多一条链路故障，路径不变；
给定故障后，各条有效探测独立。漏采不参与似然，不能当作成功。

## 贝叶斯定位

记候选故障为 $h$，探测路径为 $p_i$，失败结果为 $y_i=1$。
若 $h$ 在路径上，失败概率为 $q_1$；否则为背景概率 $q_0$。

$$P(h\mid y) \propto P(h)\prod_i q_i(h)^{y_i}(1-q_i(h))^{1-y_i}$$

健康先验为 $\pi_0$，其余概率均分给链路。成功探测会降低它所经过链路的后验，
所以只给失败路径投票会丢失信息。实现使用对数似然与 log-sum-exp，避免连乘下溢。

`fit` 用带标签训练数据估计两个失败率与健康先验：每个 Bernoulli 参数使用
Beta(1,1) 后验均值 `(positive + 1) / (total + 2)`。这是平滑后的点估计，
推断时没有积分掉参数不确定性。训练过的逻辑回归是另一个基线，特征见实验说明。

## 为什么有时无法区分

对每条链路构造路径签名：它是否经过每一条非漏采探测。
两条链路签名相同，在此模型下就有完全相同的观测似然；当前数据无法区分它们。
即便先验让某个候选得分更高，也会返回 `ambiguous`。

演示中 `core` 与 `database` 总是同时出现在失败路径中，成功路径均不经过它们。
`r1 → r2` 只覆盖 `core`，因此能带来额外区分信息。

## 下一条探测

令 $H$ 为当前故障分布，$Y_p$ 为候选探测结果。计算条件互信息：

$$IG(p)=\mathcal H(Y_p)-\sum_h P(h\mid y)\mathcal H(Y_p\mid h)$$

这等于测量前后故障熵的期望下降。将 `IG / cost` 最大的候选排在最前面。
成本来自调用者，必须为正；未提供时为 1。该策略每次选择一步，不保证多步预算下全局最优。
探测结果只能增加或减少某个具体故障的概率；期望熵下降不代表每次实际观测都让熵下降。

## 输出怎么用

`candidate` 表示排名第一的候选达到阈值，且路径签名可区分；它不是已确认根因。
`review` 表示概率未达阈值，`ambiguous` 表示签名无法区分，`insufficient_evidence`
表示没有有效观测。健康候选满足阈值时返回 `consistent_with_healthy`。

报告中的 log Bayes factor 比较第一和第二候选：正值支持第一候选，负值支持第二，零表示无区分力。
它只分解观测似然，不包含先验比值。

## 已有研究与本项目的位置

- [Flock，2023](https://arxiv.org/abs/2305.03348)：研究数据中心网络中的概率故障定位与大规模推断。本项目未复现其算法或比较其性能。
- [NetMedic，SIGCOMM 2009](https://www.microsoft.com/en-us/research/publication/detailed-diagnosis-in-enterprise-networks/)：研究细粒度依赖与故障诊断。本项目仅处理已知探测路径上的链路候选。
- [Active Diagnosis under Persistent Noise，AISTATS 2011](https://proceedings.mlr.press/v15/bellala11a.html)：讨论噪声下的主动诊断。本项目的条件独立噪声假设更简单，不能把重复告警当作独立测量。

当前工作是实现、实验协议和诊断解释，尚无新算法或真实网络收益的证据。
下一步需要接入实际探测，检验模型假设，再决定是否引入更复杂的方法。
